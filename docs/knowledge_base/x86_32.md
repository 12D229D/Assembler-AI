# Manual Técnico: Arquitectura IA-32 / x86 de 32 Bits (`x86-32`)

**Categoría / Etiqueta**: `x86-32`  
**Descripción Corta**: Arquitectura x86 de 32 bits (también conocida como IA-32), introducida con el procesador Intel 80386.  
**Estado**: Estándar Histórico / Compatibilidad Legacy  
**Nivel de Abstracción**: Sistemas de 32 Bits y Memoria Plana

---

## 1. Introducción a IA-32

La arquitectura **x86-32** (denominada comercialmente por Intel como **IA-32**) revolucionó la informática personal en 1985 con la llegada del microprocesador Intel 80386. Su principal avance fue el salto a **registros de 32 bits**, un **espacio de direccionamiento virtual de 4 GB** ($2^{32}$ bytes) y la introducción de una **Unidad de Gestión de Memoria (MMU)** avanzada con soporte para paginación por hardware.

---

## 2. Características Arquitectónicas Clave

### 1. Modelo de Memoria Plana (Flat Memory Model)
A diferencia del complejo direccionamiento segmentado de 16 bits (`segment:offset`), IA-32 permite definir segmentos que abarcan la totalidad del espacio direccionable (0x00000000 a 0xFFFFFFFF), simplificando drásticamente el desarrollo de software en C y Ensamblador.

### 2. Paginación y PAE (Physical Address Extension)
- **Paginación estándar**: Páginas de 4 KB gestionadas mediante Directorio de Páginas (*Page Directory*) y Tabla de Páginas (*Page Table*).
- **PAE (Intel Pentium Pro)**: Extiende el bus de direcciones físicas a 36 bits (hasta 64 GB de RAM física) mediante tablas de paginación de 3 niveles, manteniendo el espacio virtual por proceso en 4 GB.

### 3. Anillos de Protección (Privilege Rings)
- **Ring 0 (Kernel Mode)**: Control total sobre el hardware, instrucciones privilegiadas (`cli`, `sti`, `hlt`, `lss`).
- **Ring 3 (User Mode)**: Espacio aislado para aplicaciones de usuario. Los accesos indebidos causan un fallo de protección general (*General Protection Fault - GPF*).

## 3. Mapa de Registros de 32 Bits

```
 31                                 16 15            8 7              0
+-------------------------------------+---------------+----------------+
|                                     |      AH       |       AL       |
+-------------------------------------+---------------+----------------+
|                                     |               AX               |
+----------------------------------------------------------------------+
|                                 EAX                                  |
+----------------------------------------------------------------------+
```

- **Registros Extendidos de Propósito General**: `EAX`, `EBX`, `ECX`, `EDX`, `ESI`, `EDI`, `EBP`, `ESP`.
- **Registro de Estado e Instrucción**: `EIP` (Instruction Pointer 32-bit), `EFLAGS`.

## 4. Ejemplo de Código Ensamblador IA-32 (NASM / Linux ELF32)

```nasm
bits 32
section .data
    msg db 'Ensamblador IA-32 (x86-32) activo', 0xA
    len equ $ - msg

section .text
    global _start

_start:
    ; Llamada al sistema sys_write en Linux i386 (int 0x80)
    mov eax, 4          ; Número de syscall (sys_write)
    mov ebx, 1          ; File Descriptor: stdout
    mov ecx, msg        ; Puntero al búfer de memoria
    mov edx, len        ; Longitud del mensaje
    int 0x80            ; Invocar kernel de 32 bits

    ; Llamada al sistema sys_exit
    mov eax, 1          ; Número de syscall (sys_exit)
    mov ebx, 0          ; Código de salida 0
    int 0x80
```

## 5. Relevancia y Prospectiva

En el ecosistema de **Assembler-AI**, el conocimiento de `x86-32`:
1. Permite analizar ejecutable legados (PE32 en Windows, ELF32 en Linux).
2. Es fundamental en la ingeniería inversa, análisis de malware y seguridad informática (explotación de desbordamientos de búfer en pila / *Stack Buffer Overflow*).
3. Sirve de puente conceptual para entender las extensiones de 64 bits (AMD64).
